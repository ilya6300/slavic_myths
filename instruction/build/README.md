# Сборки: Яндекс Игры и Steam

Один репозиторий, ветка `main`, две команды. Игровой код общий. Расходится только платформенный слой: реклама и оболочка.

Постоянные ветки «яндекс» и «стим» не заводить. Отличие умещается во флаг сборки.

## Что уже есть

Сейчас в `package.json` одна боевая сборка:

```bash
npm run build
```

Это `tsc -b && vite build`. На выходе папка `dist/`: `index.html`, JS, CSS и ассеты. Это веб-сайт, не exe. Эту команду и архив `dist/` отдавать Яндексу.

Оболочка для exe подготовлена, но это не стимовский продукт: реклама не вырезана, SDK Яндекса по-прежнему не подключён.

```bash
npm run build:electron
```

Команда собирает Vite в режиме `electron` (`base: './'`, файл `.env.electron` включает тестовую заглушку рекламы) и пакует `dist/` через Electron в `release/*.exe`. Игровой код Electron не импортирует. `npm run build` упаковщик не вызывает.

## Яндекс Игры

Яндекс хостит статику. Ему нужен архив сайта, не программа.

Когда команда будет заведена, сборка:

```bash
npm run build:yandex
```

Она обязана:

1. Собрать Vite **без** флага Steam.
2. Подключить SDK Яндекса (`YaGames`) только в этой сборке.
3. Оставить кнопки rewarded: сундук, энергия и остальные точки рекламы вызывают `adsService` → живое видео.
4. Положить результат в каталог вроде `dist/` и больше ничего туда не класть.

В архив для консоли Яндекса входит содержимое этого каталога: `index.html`, скрипты, стили, ассеты.

В архив не входит:

- `node_modules/`
- исходники `src/`
- Electron, Tauri, `.exe`, `.dll`
- папка инструкции и черновики арта

Проверка перед загрузкой: в архиве нет файлов `.exe`, `.dll`, `electron.exe` и нет каталога `node_modules`.

## Steam

Steam запускает exe. Оболочка (Electron) только показывает тот же сайт в окне и пакует его в установщик.

Когда команда будет заведена, сборка:

```bash
npm run build:steam
```

Она обязана:

1. Собрать тот же фронт с флагом цели Steam (`VITE_TARGET=steam`).
2. В этом режиме не вызывать ролик и не подключать скрипт Яндекса. Кнопки, которые существуют только ради рекламы, либо скрыты, либо сразу выдают награду — это решается в игровом коде по флагу, не отдельной копией проекта.
3. Завернуть полученный `dist/` в Electron и получить exe.
4. Сохранения оставить локальными. Облако Яндекса в exe не переносится. Steam Cloud — отдельное подключение, не часть первой упаковки.

## Electron не попадает в сборку Яндекса

Не попадает, если держать границу такой:

| | Яндекс | Steam |
|---|---|---|
| Команда | `vite build` | `vite build` + упаковка Electron |
| Зависимость Electron | не импортируется игрой | только скрипт упаковки |
| Что отдаём наружу | zip с `dist/` | exe |

Electron ставится как dev-зависимость упаковщика, не как зависимость игры. `src/` его не импортирует. Vite кладёт в `dist/` только то, до чего доходит импорт из приложения. Неимпортированный Electron в сайт не вшивается.

`npm run build:yandex` не должен вызывать упаковщик. Даже если Electron лежит в `node_modules` на машине разработчика, в архив для Яндекса берётся только `dist/`.
